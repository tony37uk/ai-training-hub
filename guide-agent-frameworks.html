Choosing an Agent Framework

⏱️ 15 min read 🟡 Intermediate 🧠 Comparison, no coding

Once you understand how multi-agent systems work, the next question is: what do I build one with? There are a lot of frameworks, they all use different names for similar ideas, and the landscape changes fast. This guide compares the main options in plain English and helps you pick one.

💡 You might not need a framework. If your swarm helps you with tasks on your own computer, Claude Code's subagents already do the job with no code at all. See Build a Swarm with Claude Code Subagents. Frameworks matter when you're building an agent into an app or service other people will use.

Quick Decision Guide

  • →Your organisation runs on Azure / Microsoft 365, or uses .NET: start with Microsoft Agent Framework.
  • →You want an agent that can work with files and run commands, like Claude Code, inside your own app: use the Claude Agent SDK.
  • →You're building on OpenAI models and want simple handoffs between agents: use the OpenAI Agents SDK.
  • →You need precise control over every step, loops, and pausing for human approval: use LangGraph.
  • →You want to describe a team of roles quickly and see it work: try CrewAI.

A Closer Look

🪟 Microsoft Agent Framework

Microsoft's open-source framework for agents and multi-agent workflows. It's the direct successor to Semantic Kernel and AutoGen, built by the same teams, combining Semantic Kernel's enterprise features with AutoGen's multi-agent ideas. It separates agents (open-ended, decide their own steps) from workflows (a defined process with an explicit order). For someone working in EUC and Azure, this is the most natural fit for production work.

🟣 Claude Agent SDK

Lets you build Claude Code's agent into your own Python or TypeScript program: the same built-in tools, agent loop, subagents, hooks, permissions and MCP connections. If you've already built a swarm with Claude Code subagents, the ideas carry straight over. It's billed through a Claude API key.

🟢 OpenAI Agents SDK

OpenAI's lightweight framework, built around agents, handoffs, guardrails and tracing. A handoff shows up to the model as a tool, such as transfer_to_refund_agent, so routing between specialists is very simple to set up.

🔗 LangGraph

Models a workflow as a graph: each step is a node, arrows decide what runs next, and a shared state object carries information between steps. It has checkpoints for saving progress and can pause to ask a human. More to learn, but the most control.

👥 CrewAI

Built around the idea of a crew: you describe agents by role and goal, give them tasks, and let them collaborate. Flows sit on top to control state and order. Often the fastest way to get a multi-agent prototype running.

A Note on OpenAI Swarm

⚠️ Many tutorials still use OpenAI Swarm, and you shouldn't build on it. Swarm was an experimental teaching tool released in 2024. OpenAI shut it down in March 2025 because it lacked memory, tracing and safety guardrails, and pointed developers to the OpenAI Agents SDK instead. Swarm tutorials are still useful for understanding handoffs; just use the Agents SDK for anything real.

Questions to Ask Before You Choose

1

What language does your team use?

.NET points to Microsoft Agent Framework. Python and TypeScript open up every option.

2

Which AI models and cloud are you committed to?

Vendor frameworks work best with their own models and platforms. LangGraph and CrewAI are model-neutral.

3

Do you need approvals and audit trails?

For anything that changes real systems, look for built-in human-approval steps, tracing and logging. These matter more than clever orchestration.

4

Who will maintain it?

A framework your team already knows beats a better one nobody can support. Check documentation quality and how actively it's updated.

Quick Reference: Do's and Don'ts

✅ Do this

  • Learn the patterns before the framework
  • Pick what fits your language and cloud
  • Prototype small before committing
  • Check the docs are current (this area moves fast)
  • Insist on logging and human approval steps

❌ Avoid this

  • Building on OpenAI Swarm
  • Choosing on hype or GitHub stars alone
  • Mixing several frameworks in one project
  • Using a framework where Claude Code would do
  • Following tutorials more than a year old without checking
