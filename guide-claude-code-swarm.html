🛠️ Hands-on Guide

Build a Swarm with Claude Code Subagents

⏱️ 45–60 min 🟡 Intermediate 💻 Needs Claude Code

In this hands-on guide you'll build a small swarm of AI agents that help maintain this website. You'll create four specialist subagents in Claude Code (a link checker, a researcher, a writer and a reviewer), then run them together to find, add and check new content.

💡 New to the ideas? Multi-Agent Systems & Swarms Explained covers the patterns you'll use here. This guide combines two of them: orchestrator–worker (agents working in parallel) and a pipeline (write, then review).

What You'll Build

AgentJobToolsCan edit?
link-checkerFinds broken links across the siteRead, search, fetch web pagesNo
resource-researcherFinds new free learning resourcesWeb search, fetch, ReadNo

hub-reviewerChecks the change against CLAUDE.mdRead, search, terminal (for git diff)No, by instruction*

Notice that only one agent is meant to change anything. That's deliberate: it's the principle of least privilege applied to a swarm.

* The reviewer needs terminal access to run git diff. A terminal could change files, so its instructions forbid edits, and Claude Code still asks your permission before running commands.

Before You Start

  • 1Claude Code installed (see Getting Started with Claude Code)
  • 2A copy of this site's repo on your computer: git clone https://github.com/tony37uk/ai-training-hub.git
  • 3A terminal open in the ai-training-hub folder

How Subagents Work

A subagent is a helper that Claude Code can hand a task to. Each one:

  • →Is a Markdown file with a short settings block at the top (called frontmatter). The text underneath becomes its instructions.
  • →Lives in .claude/agents/ in your project (shared with anyone who uses the repo) or ~/.claude/agents/ (available in all your projects).
  • →Runs in its own context window. It doesn't see your conversation, and only its summary comes back, so your main session stays tidy.
  • →Can run in parallel with other subagents.
SettingWhat it does
name (required)The agent's ID, in lowercase with hyphens
description (required)When Claude should use it. Claude reads this to decide whether to delegate, and "use proactively" encourages it to
toolsWhich tools it may use. If you leave this out it gets all of them, so always set it
modelhaiku (fast, cheap), sonnet, opus, or inherit to match your session

Create the Four Agents

1

Make the agents folder

In your terminal, inside the ai-training-hub folder:

mkdir -p .claude/agents (macOS/Linux) or mkdir .claude\agents (Windows PowerShell)

2

Add each agent file

Create the four files below in .claude/agents/. Or let Claude Code do it: start claude, paste a file's contents and say "save this as .claude/agents/link-checker.md".

.claude/agents/link-checker.md

---
name: link-checker
description: Checks every link in data.json and the guide pages and reports broken ones. Use proactively after links are added or changed.
tools: Read, Grep, Glob, WebFetch
model: haiku
---

You check links on the AI Training Hub. You never edit files.

1. Collect every "url" and "subPageUrl" value from data.json, and every
   href in the guide-*.html and resources-*.html pages.
2. For local links (e.g. guide-openclaw.html), check the file exists.
3. For web links, fetch each one and note any that fail, redirect to an
   error page, or no longer match the card's description.

Reply with a short table: link, where it appears, status (OK / broken /
check manually), and a one-line reason for anything not OK.

.claude/agents/resource-researcher.md

---
name: resource-researcher
description: Finds new, free, high-quality learning resources for the AI Training Hub on a given topic. Use when asked to suggest or find new content.
tools: WebSearch, WebFetch, Read
model: sonnet
---

You find learning resources for an AI training site aimed at IT
professionals. You never edit files.

- Read data.json first so you don't suggest anything already listed.
- Prefer official sources (vendor docs, course providers, the original
  author) over blogs that summarise them.
- Only suggest https links, free or free-to-audit content, and pages you
  have actually opened and checked.

Return up to 3 candidates, each with: title, url, who publishes it,
whether it's free, and a one-sentence description written for a beginner.

.claude/agents/card-writer.md

---
name: card-writer
description: Adds new resource cards to data.json in the hub's existing format. Use when a resource has been chosen and needs adding to the site.
tools: Read, Edit
model: sonnet
---

You add cards to data.json for the AI Training Hub. Only ever edit
data.json.

- Put the card in the right section (links, guides, videos).
- Copy the exact shape of the existing cards in that section: tag,
  tagClass, title, description, url, linkLabel (and thumb/thumbBg for
  videos).
- Keep descriptions to one plain-English sentence, and include the words
  people would filter by (for example "agents" or "Claude").
- Keep the file valid JSON.

Finish by listing exactly what you added.

.claude/agents/hub-reviewer.md

---
name: hub-reviewer
description: Reviews changes to the AI Training Hub against CLAUDE.md and the README before they are committed. Use after any change to data.json or the HTML pages.
tools: Read, Grep, Glob, Bash
model: sonnet
---

You review changes before they are committed. You never edit files.

1. Run `git diff` to see what changed.
2. Check data.json is valid JSON and new cards match the existing format.
3. Check every rule in CLAUDE.md: https links only, new-tab links have
   rel="noopener noreferrer", no secrets or email addresses, user content
   escaped.
4. Check new descriptions are clear, accurate and free of typos.

Reply with PASS or CHANGES NEEDED, followed by a numbered list of any
problems and how to fix each one.
✍️ Make them your own. These are starting points. Change the instructions to suit how you want the hub to look and sound. The more specific the instructions, the better each agent performs.
3

Restart Claude Code

Claude Code picks up changes to agent files within seconds, but a brand-new agents folder needs a restart. Exit with /exit and run claude again.

Run Your Swarm

You can call one agent by name, or @-mention it to guarantee it runs:

Use the link-checker subagent to check every link on the site.
@"link-checker (agent)" check the links in data.json

Now run the whole team. Paste this into Claude Code, and it acts as the orchestrator:

I want to add new multi-agent learning resources to the hub.

1. In parallel:
   - use the link-checker subagent to check all existing links
   - use the resource-researcher subagent to find 3 free resources
     about multi-agent systems
2. Show me the researcher's candidates and the broken-link report, then
   wait for me to pick a resource.
3. Use the card-writer subagent to add the one I pick to data.json.
4. Use the hub-reviewer subagent to review the change and fix anything it
   flags. Don't commit until I say so.

Watch what happens: the link checker and researcher work at the same time, each in its own context. Then the writer and reviewer run one after the other. Your main session only receives their summaries.

⚠️ Stay in the loop. Step 2 of the prompt makes Claude stop and ask you before anything is changed. Keep checkpoints like this until you trust your agents.

Check and Publish the Result

1

Look at the site

Run python3 -m http.server 8000 and open http://localhost:8000. Check the new card appears and its link works.

2

Commit the agents and the change

Ask Claude Code to "commit the new agents and the data.json change, then push". Committing .claude/agents/ means the agents travel with the repo, ready for next time.

Going Further: Agent Teams

Subagents report back to your session but don't work together as a team. Claude Code also has an experimental agent teams feature, where several Claude Code sessions share a task list and message each other directly, so they can challenge each other's findings.

Subagents

Report results back to your main session. Lower cost. Best for focused jobs where only the result matters.

Agent teams

Teammates talk to each other and share a task list. Much higher token cost. Best for reviews, research and debate.

Agent teams are off by default. To try them, add this to your Claude Code settings.json:

settings.json

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

Then describe the team you want. Your subagent files can be reused as teammates:

Spawn three teammates to review the hub's How-To Guides section:
- one using the hub-reviewer agent type, checking accuracy and the CLAUDE.md rules
- one checking the guides read well for a complete beginner
- one looking for gaps: topics an IT professional would expect but can't find
Have them share and challenge each other's findings, then give me one
prioritised list of improvements. Don't change any files.
💡 Anthropic suggests starting with 3–5 teammates and with research or review tasks that don't involve writing code, so you see the benefit without teammates editing the same files.

Troubleshooting

ProblemFix
Claude doesn't seem to know about an agentRestart Claude Code. Check the file is in .claude/agents/, ends in .md and has name and description lines.
Claude does the work itself instead of delegatingName the agent in your prompt, or @-mention it. Make its description say clearly when to use it.
An agent changed something it shouldn'tTighten its tools line. Read-only agents should only have Read, Grep, Glob and web tools.
It's using a lot of your usage allowanceUse model: haiku for simple jobs like link checking, and run fewer agents at once.
Asked for a team but got subagentsCheck agent teams are enabled, then ask again and explicitly request an agent team.

Quick Reference: Do's and Don'ts

✅ Do this

  • Always set a tools list
  • Give one agent the right to edit, others read-only
  • Write descriptions that say when to use the agent
  • Add a "wait for me" step before changes
  • Commit .claude/agents/ to the repo

❌ Avoid this

  • Leaving out tools (the agent gets everything)
  • Agents with overlapping jobs
  • Putting passwords or keys in agent files
  • Letting agents commit or push unreviewed work
  • Agent teams for small, routine tasks
